Covariates in a model-based meta-analysis

Three published population models are used as the input to a meta-analysis: each generates the aggregate data its own study design and population would have produced, and one unifying model is then fitted to all three at once. No individual records exist at any point.

The covariate is the point of the exercise. Each study’s subjects span a distribution of body weights, and that distribution differs between studies — which is not incidental, because between-study variation in the covariate distribution is the only thing that identifies a covariate coefficient from aggregate data. Two ways of describing those subjects are compared:

  • summary statistics — a mean, a standard deviation and a correlation, which is what a baseline-characteristics table reports;
  • an R-vine copula per study — a full joint distribution with its own margins and dependence structure, which is what you would fit if you had access to the individual covariate records even though the outcomes remain aggregate.

Each is run through both estimators, and each estimator is run in its ordinary form and with covariate reweighting enabled.

The three published models

Weight acts on clearance, which carries the between-subject random effect. The three models differ in structure, in their parameter values, and in the designs they were developed under — a single dose with rich sampling, a multiple-dose regimen sampled at steady state, and a sparse two-sample design.

mod_A <- function() {          # rich single dose
  ini({lcl <- log(3.2); lv <- log(21); clwt <- 0.75; clcr <- 0.45
       eta.cl ~ 0.09; prop.err <- 0.13})
  model({cl <- exp(lcl + eta.cl) * (WT / 70)^clwt * (CRCL / 95)^clcr
         v  <- exp(lv)
         d/dt(centr) <- -cl / v * centr
         cp <- centr / v
         cp ~ prop(prop.err)})
}
mod_B <- function() {          # multiple dose, steady state
  ini({lcl <- log(2.6); lv <- log(25); clwt <- 0.68; clcr <- 0.38
       eta.cl ~ 0.055; prop.err <- 0.16})
  model({cl <- exp(lcl + eta.cl) * (WT / 70)^clwt * (CRCL / 95)^clcr
         v  <- exp(lv)
         d/dt(centr) <- -cl / v * centr
         cp <- centr / v
         cp ~ prop(prop.err)})
}
mod_C <- function() {          # sparse
  ini({lcl <- log(3.9); lv <- log(18); clwt <- 0.82; clcr <- 0.52
       eta.cl ~ 0.12; prop.err <- 0.11})

Version 1: the covariate as summary statistics

Each study reports a mean and standard deviation of weight. This is the ordinary case, and it is all a baseline-characteristics table gives you.

## A baseline table gives a mean and SD per covariate and a correlation between
## them. That correlation only reaches the likelihood if the covariates are drawn
## JOINTLY, so it is expressed as a Gaussian copula over the two margins -- the
## simplest joint distribution consistent with what was reported.
## Both margins are LOGNORMAL, matched to the reported mean and SD. A normal
## margin would be the obvious reading of "mean and standard deviation", but it
## puts mass at and below zero -- and (CRCL/95)^clcr with a negative base and a
## fractional exponent is NaN, which reaches the objective as a missing value
## rather than as an error. A positive covariate needs a positive margin.
ln_par <- function(m, s) c(meanlog = log(m^2 / sqrt(s^2 + m^2)),
                           sdlog   = sqrt(log(1 + s^2 / m^2)))
gauss_pair <- function(pw, pc, rho) function(u) {
  z  <- stats::qnorm(u)
  z2 <- rho * z[, 1] + sqrt(1 - rho^2) * z[, 2]
  cbind(WT   = stats::qlnorm(stats::pnorm(z[, 1]), pw[1], pw[2]),
        CRCL = stats::qlnorm(stats::pnorm(z2),     pc[1], pc[2]))
}
mk_summary <- function(m_wt, s_wt, m_cr, s_cr, rho) {
  pw <- ln_par(m_wt, s_wt); pc <- ln_par(m_cr, s_cr)
  list(WT    = list(quantile = function(u) stats::qlnorm(u, pw[1], pw[2])),
       CRCL  = list(quantile = function(u) stats::qlnorm(u, pc[1], pc[2])),
       joint = gauss_pair(pw, pc, rho))
}
WT_SUMMARY <- list(
  A = mk_summary(58, 13,  98, 22, 0.45),
  B = mk_summary(74, 23,  92, 26, 0.38),
  C = mk_summary(91, 16, 105, 19, 0.52))

Version 2: the covariate as an R-vine copula

Real patient statistics are dependent: weight travels with height, and renal function with age. An R-vine describes that joint distribution directly, with its own margins and its own pair-copula for each edge of the tree — so the tails and the asymmetries survive, which a correlation matrix cannot represent.

Each study gets its own vine, fitted the usual way: non-parametric marginals, the probability-integral transform, then an unconstrained fit that selects the structure from the data.

fit_vine <- function(seed) {
  set.seed(seed); m <- 4000
  ## an individual covariate record, of the kind a vine would be fitted to
  age  <- stats::rgamma(m, 9, 0.25)
  ht   <- 150 + 0.25 * age + stats::rnorm(m, 0, 9)
  wt   <- exp(log(70) + 0.012 * (ht - 160) + 0.25 * stats::rnorm(m))
  crcl <- pmax(20, 130 - 0.9 * age + 0.35 * wt + stats::rnorm(m, 0, 12))
  U    <- apply(cbind(wt, ht, age, crcl), 2L,
                function(z) rank(z) / (length(z) + 1))
  ## free R-vine: no structure imposed, families selected from the data. Only
  ## the COPULA is kept -- the margins come from the reported summaries.
  list(vc = rvinecopulib::vinecop(U, family_set = "all"))
}

The sampler must be driven by admixr2’s own uniforms, or the objective stops being a deterministic function of the parameters and its finite differences become noise. rvinecop() draws its own randomness and accepts no such input; inverse_rosenblatt() maps supplied uniforms to vine-distributed ones and is what makes this work. The two are distributionally indistinguishable — checked in validation/covariate-rvine-sampling-check.R, where the mean log vine density of the two agrees to 0.18 standard errors.

vine_sampler <- function(vc, pw, pc) {
  function(u) {
    ## admixr2 supplies one uniform column per DECLARED covariate (WT, CRCL);
    ## the vine is 4-dimensional, so the two nuisance dimensions are filled from
    ## the same stream by a fixed deterministic rotation -- still a function of
    ## `u` alone, which is what keeps the objective deterministic.
    uu <- cbind(u[, 1], (u[, 1] + u[, 2]) %% 1, (u[, 1] + 2 * u[, 2]) %% 1, u[, 2])
    v  <- rvinecopulib::inverse_rosenblatt(
      pmin(pmax(uu, 1e-9), 1 - 1e-9), vc)
    ## the vine is fitted over four covariates, but only the two the model
    ## reads are returned -- the others are in the vine because they carry the
    ## dependence that shapes these two, not because the model needs them
    cbind(WT   = stats::qlnorm(v[, 1], pw[1], pw[2]),
          CRCL = stats::qlnorm(v[, 4], pc[1], pc[2]))
  }
}
## The vine supplies the DEPENDENCE; the margins are the same lognormals version
## 1 reports. That is what makes the two versions comparable -- they describe the
## same patients and differ only in how the two covariates are linked.
##
## Fitting the vine to synthetic data with its own marginal scales instead was
## the first attempt, and it silently changed the population: study B's
## creatinine clearance came out centred at 124 rather than the reported 92, so
## the two versions were fitting different patients and their coefficients were
## never comparable. Same margins, different dependence.
VINES <- list(A = fit_vine(11), B = fit_vine(12), C = fit_vine(13))
PARS  <- list(A = c(58, 13,  98, 22), B = c(74, 23,  92, 26),
              C = c(91, 16, 105, 19))
WT_VINE <- lapply(names(VINES), function(k) {
  vc <- VINES[[k]]$vc
  pw <- ln_par(PARS[[k]][1], PARS[[k]][2])
  pc <- ln_par(PARS[[k]][3], PARS[[k]][4])
  list(WT    = list(quantile = function(u) stats::qlnorm(u, pw[1], pw[2])),
       CRCL  = list(quantile = function(u) stats::qlnorm(u, pc[1], pc[2])),
       joint = vine_sampler(vc, pw, pc))
})

The unifying model

One model is fitted to all three studies. It starts away from every generating model, so nothing is being handed the answer.

mod_unify <- function() {
  ini({lcl <- log(2.0); lv <- log(30); clwt <- 0.50; clcr <- 0.25
       eta.cl ~ 0.20; prop.err <- 0.25})
  model({cl <- exp(lcl + eta.cl) * (WT / 70)^clwt * (CRCL / 95)^clcr
         v  <- exp(lv)
         d/dt(centr) <- -cl / v * centr
         cp <- centr / v
         cp ~ prop(prop.err)})
}

Fitting: two estimators, ordinary and reweighted

adgh integrates the covariate on a deterministic product grid; admc integrates it by simulating subjects. cov_reweight = TRUE changes how that integral is evaluated in both: the covariate is carried in an importance weight rather than in the grid or the sample, so adgh drops the covariate dimension from its grid and admc shares one simulation ensemble across studies that differ only in their covariate distribution.

It is opt-in and self-declining. The substitution it relies on — that the prediction depends on the covariate and the random effect only through their sum — is a property of the model, and it is checked numerically once per fit rather than inferred from how the model is written. Anything that fails the check keeps the ordinary path, so the flag can only make a qualifying fit cheaper.

fit_one <- function(studies, est, reweight) {
  ctl <- if (est == "adgh")
    adghControl(studies = studies, n_nodes = 7L, print = 0L,
                covMethod = "none", maxeval = 400L, cov_reweight = reweight)
  else
    admControl(studies = studies, n_sim = 3000L, print = 0L,
               covMethod = "none", maxeval = 400L, cov_reweight = reweight)
  t0 <- Sys.time()
  f  <- try(suppressWarnings(suppressMessages(
    nlmixr2est::nlmixr2(mod_unify, admData(), est = est, control = ctl))),
    silent = TRUE)
  dt <- as.numeric(difftime(Sys.time(), t0, units = "secs"))
  if (inherits(f, "try-error")) {
    ## Distinguish a DELIBERATE refusal from a failure. Labelling both "refused"
    ## would present a bug as a design decision, which is the more dangerous of
    ## the two ways to be wrong here.
    msg <- conditionMessage(attr(f, "condition"))
    st  <- if (grepl("does not support|cannot represent|joint", msg))
      "refused" else paste0("ERROR: ", substr(msg, 1, 90))
    return(data.frame(estimator = est, reweight = reweight, status = st,
                      lcl = NA, lv = NA, clwt = NA, clcr = NA,
                      objective = NA, secs = dt))
  }
  ax <- f$env$admExtra
  data.frame(estimator = est, reweight = reweight, status = "fitted",
             lcl = unname(ax$struct[["lcl"]]), lv = unname(ax$struct[["lv"]]),
             clwt = unname(ax$struct[["clwt"]]),
             clcr = unname(ax$struct[["clcr"]]),
             objective = f$objective, secs = dt)
}

Act I: what the analysis is actually given

The three studies have to differ in their covariate distributions for the coefficients to be estimable at all, and the two dependent versions have to actually carry dependence. Both are worth seeing rather than asserting.

The marginals differ between studies, which is what makes the coefficients estimable; the independent version shows no tilt, and both dependent versions do.

Act II: what the fits concluded — and the number that looks wrong

Each fit is summarised by what it says about clearance: how it scales with weight at a typical creatinine clearance, and with creatinine clearance at a typical weight. The three generating models are drawn for comparison — there is no single truth here, since the unifying model is one structure reconciling three, so the generating curves bracket rather than define the answer.

The three covariate descriptions barely matter, and one coefficient is displaced. Both are worth reading off the plot rather than the table.

The weight exponent comes out at 0.69, 0.61 and 0.66 across the three descriptions, against generating values of 0.68–0.82: consistent between descriptions, and at or just below the range the generating models span. The creatinine-clearance exponent is 1.48–1.58 everywhere, against generating values of 0.38–0.52 — high by roughly a factor of three, and equally so in all three.

That the three descriptions agree is the robustness result: how the covariates are described, and whether their dependence is modelled at all, moves the estimates by less than the difference between the generating models. The displacement in the creatinine-clearance exponent is therefore not something the covariate handling caused — it is a property of reconciling three different generating structures into one, and would need a profile over that coefficient, or a wider unifying model, to pursue.

Act III: why one coefficient is three times too steep

An exponent of about 1.5 against generating values of 0.38–0.52 is a large displacement, and it is the same in all three covariate descriptions — so whatever causes it, the covariate handling does not.

It is confounding, and the three studies are built to produce it. They differ in baseline clearance (lcl of log 3.2, log 2.6 and log 3.9) as well as in their covariate coefficients, while the unifying model has a single lcl. They also differ in mean creatinine clearance (98, 92 and 105). A between-study difference in baseline clearance and a between-study difference in a covariate are not separable from summary data: the only place the first can go is the slope of the second. This is the aggregate-data form of the ecological fallacy, and it is a property of the design rather than of the estimator.

Seeing it is easier than reading it. Each study has a true relationship between clearance and creatinine clearance — a line whose SLOPE is the covariate effect we want. But each study also sits at its own HEIGHT, because its baseline clearance differs. A single model with one baseline cannot reproduce three heights, so it tilts instead: the only way one line can pass near three offset segments is to be steeper than any of them.

On the left the three coloured segments sit at visibly different heights, and the dashed line — the model actually fitted — is far steeper than any of them. On the right, where the studies share a generating model, the segments line up and a single line reproduces them with the right slope. Nothing about the estimator differs between the two panels; only whether the studies were the same underneath.

The way to show that is to remove the confounding and refit. Below, all three studies are generated from ONE model — same lcl, same coefficients — and differ only in their design and their covariate distribution, which is what the coefficients are supposed to be estimated from.

Every parameter comes back, the creatinine-clearance exponent included. So the displacement in the earlier tables is not the estimator, the covariate description, or the reweighting — it is three different models being summarised by one, and it would appear in exactly the same way in an individual-level analysis of the same three studies.

The practical reading is that a covariate coefficient estimated across studies carries whatever else differs between those studies. Where the studies are structurally different, as here, that is a reason to widen the unifying model or to admit a between-study term — not to trust the coefficient.

What to take away

The estimates agree across every cell that runs. That is the point of the comparison: the four combinations evaluate the same integral by different means, so agreement is evidence that the integral, and not the machinery, is what determines the answer.

Reweighting is a speed setting, not a modelling choice. It changes how the covariate integral is evaluated and nothing about what is being estimated, which is why the estimates match rather than merely resemble each other.

adgh and a dependent covariate distribution do not combine. That is a refusal and not a limitation to work around: a product grid assumes independence, and producing a number from it would be worse than declining. Use admc when the covariates are dependent.

Finally, a covariate coefficient is only estimable here because the three studies have different weight distributions. Three studies drawn from one population would leave the likelihood exactly flat along a trade-off between the coefficient and the between-subject variance, and any estimate reported from such a fit would be the optimiser’s stopping point rather than a result.
